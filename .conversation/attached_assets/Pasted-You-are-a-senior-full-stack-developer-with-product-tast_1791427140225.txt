1. PRODUCT
StoryBowl — "Ordinary things. Unexpected stories."
A desktop-first browser toy. The user picks 3–10 everyday objects by clicking
or dragging them into a bowl, chooses a mood (Calm / Funny / Mystery), and
presses "Make my story." A server endpoint asks an LLM for a ~55-word story
that connects the objects; the app shows it and reads it aloud with the
browser's speech synthesis. Replay re-reads the saved text with zero new
requests. New story keeps the ingredients and asks for a fresh take. English
only. This is a personal learning prototype for adult testers, not a
child-directed product.

2. STACK
- React + TypeScript + Vite + Tailwind CSS. lucide-react for icons.
- Plain React state (useState/useReducer). Components: ObjectShelf,
  ObjectTile, StoryBowl, MoodPicker, StoryResult, HowItWorks; one hook:
  useSpeech.
- One server function, POST /api/story, plus GET /api/status, using this
  platform's native server option (Express on Replit; a serverless or edge
  function on Bolt or Lovable).
- Call Groq's chat-completions REST endpoint directly with fetch, no SDK, so

5. INTERACTION AND STATE
- Click and drag both add; adding an object already in the bowl is a no-op;
  at ten, show "The bowl is full (10 of 10)". Drops outside the stage do
  nothing. Keyboard: tiles are buttons; Enter/Space adds.
- Removing an ingredient updates the count and button state immediately.
- Changing ingredients or mood stops speech, cancels in-flight requests,
  clears the result so an old story is never shown against a new selection,
  and does not auto-generate.
- While generating: a small loader and the text "Finding the thread…", no
  percentages, the button disabled, Reset still available. Use AbortController
  plus an incrementing request id and ignore any response whose id is stale.
- Reset: stop speech, abort requests, clear bowl, result, search and error,
  return mood to Calm; a late response must not repopulate the page.
- Keep the last two stories in tab memory only (no persistence).
- Copy text copies "Title\n\nStory", with a select-the-text fallback when the
  clipboard API is unavailable.

6. STORY API
POST /api/story accepts exactly: { objectIds: 3–10 unique registry ids,
mood: "calm" | "funny" | "mystery", recentOpenings?: up to 2 strings of ≤160
chars }. Reject anything else with 400; body limit 8 KB. recentOpenings are
untrusted quoted text to steer away from, never instructions.
The server chooses a variation and names it in the prompt: one focal object,
a perspective (close third person, first person, or a passing onlooker), and
an ending style that fits the mood.
Call Groq with response_format { type: "json_schema", json_schema: { name:
"story", strict: true, schema: { title: string, story: string } } } — this
model supports strict mode. If the API rejects the response_format, retry
once with { type: "json_object" } and the word "JSON" in the prompt.
Temperature about 0.9. Timeout 20 seconds via AbortController.
Validate server-side: parse the JSON; story word count 45–65 (title
excluded); every selected object is mentioned, checked case-insensitively by
whether any story word starts with the object's label or one of its aliases
(≥3 characters). This is a heuristic that can produce false positives;
document that in a code comment. If anything fails, make exactly ONE repair
call that quotes the problem ("too long: 78 words", "missing: lantern, key").
If the repair also fails, return error code STORY_INVALID and keep the user's
ingredients intact on the client.
Success response: { id, objectIds, mood, language: "en", title, story,
wordCount, source: "ai" | "demo" }. Errors: { code, message } with codes
NO_API_KEY, BAD_REQUEST, RATE_LIMITED (our limiter or a 429 from Groq),
MODEL_UNAVAILABLE, PROVIDER_REFUSED, TIMEOUT, STORY_INVALID. Friendly
messages; never echo raw provider errors or credentials. Rate limit
in-memory, 20 requests per 10 minutes per IP; on Replit trust only the
platform's proxy header; document that in-memory limits reset on restart
and are not a spending cap.

7. STORY-WRITING INSTRUCTIONS (system prompt, verbatim)
"Write a tiny, complete fictional story for spoken narration. Aim for 50–60
words, excluding the title; 45–65 is acceptable. Include every selected
object naturally, using its label or a close variant. Let two or three
objects drive the action and the rest support it; do not merely list them.
Give the story a concrete situation, a change, and a satisfying final beat.
Calm is warm and unhurried. Funny lands a specific comic payoff. Mystery
has a curious reveal without horror. Avoid moral lessons, inspirational
endings, 'Once upon a time', preambles, hashtags, and explaining how the
story was written. Introduce few extra props. No explicit sexual content,
graphic violence, hateful content, or dangerous instructions. Return only
the requested JSON with a title of at most eight words and the story."

8. NARRATION (useSpeech)
Load voices with getVoices() and the voiceschanged event; pick an English
voice automatically (prefer a local default). Speak the story sentence by
sentence as a queue of utterances; this avoids the long-utterance cutoff
some browsers have. Rate about 0.95, volume 1. Cancel any existing speech
before starting new speech. Handle start, end and error; clean up on
unmount; ignore callbacks from stale utterances. After generation, start
narration as part of the user's click flow; if the browser blocks it, show
"Your story is ready. Press Play to listen." The text is always usable
without speech. Present "about 20–30 seconds" as an estimate, with no
countdown and no animation that implies real audio progress. No voice
selector in v1.
